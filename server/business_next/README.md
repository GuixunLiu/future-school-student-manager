# v0.5.0 名册核对副本

在原 v0.4.0 的 19 个文件完全不变的基础上增加独立归档、当前班级时间模板和期初名册导入。

- `python -m business_next.cli prepare-roster`明确指定来源数据库、已核对名册和服务器清单及其SHA256，先保留同一一致性快照的独立完整备份（`*.before-import.sqlite`，包含私有凭证，仅留服务器），核对完整性及逻辑指纹，再在**另一个全新私有数据库**导入。备份另有SHA256回执并保持不变。不修改来源，不覆盖现有同编号档案，不删除服务器测试资料。
- 只导入当前名册、状态、整数百分之一课时余额及班级时间模板。教师标签仅供核对，不创建账号或任课授权；不回放签到、流水、请假，不创建新生/续费或通知，不推算历史课次。
- 长期不来学生独立进入 `archived_students`，允许原班级为空；不参与应到、签到、低课时提醒。跨表编号和 ID 唯一性受数据库触发器保护。
- `serve --review-only --port 18082` 仅监听本机。所有业务写接口关闭，仅允许登录退出维护临时会话。管理员可从“长期不来归档”核对名单、原班级、余额和人数；教师和其他身份不可访问归档。
- 恢复上课逻辑保留原 ID/编号/余额，必须由管理员明确选班并核对预期余额，事务失败恢复原归档；不新增续费、新生、签到或通知。当前核对服务器不开放此写功能。
- 班级时间按快照日期保存，含隔周锚点；不生成实际课次，不把新时长写回历史。
- 当前仍未启用真实微信、家长绑定或平板同步。平板继续作为现有签到和余额来源，快照后的变化需要重新核对。

部署使用新目录、全新数据库、独立 `wxnotify-roster-review.service` 和本机 18082 端口。保留旧服务和旧数据库。复用旧 v0.4 私有虚拟环境执行新工作目录内的模块，禁止提前清理旧运行环境。核对通过后，正式切换另行操作；不能把核对副本当成已完成联网。
