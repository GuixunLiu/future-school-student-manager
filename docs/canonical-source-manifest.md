# 平板最小核对清单生成器（2026-11-01）

已实现 `server/ops/build-canonical-manifest.cjs`，仅在电脑本地读取备份和显式映射，产生候选核对接口请求正文；没有网络调用、导入、授权、扣课或历史重放。只投影姓名、学号、班级/老师身份、余额和课次事实，不输出人脸、联系方式、管理密码或请假原因。

## 输入和输出

工具导出 `build(raw, mapping, capture, now)`。`raw` 是原样UTF-8资料字符串，摘要包括原始空格和换行，不能重新序列化后冒充原文件。命令行必须同时显式给出 `--backup`、`--mapping`、`--capture-receipt`、`--output`，没有默认读取真实文件或上传行为。输出必须在Git仓库外，且独占新建，拒绝覆盖先前结果。

`capture` 严格只有 `format, sha256, bytes, captured_at`；格式为 `future-school-live-capture-v1`，摘要/字节数必须与原资料一致，采集时间须在15分钟内，允许120秒时钟超前。**采集回执是采集工具/可信操作者的声明，不是密码学时间证明。**当前尚未实现真实平板新鲜采集回执生成，不得手工用当前时间给旧备份改标签；11月1日08:21备份不因此变成新鲜资料。后续原生暂存仍须核对实际App当前状态的同一摘要，备份与当前状态有任何差异都不能启用。

`mapping` 严格包含：

- `protocol=1, org_id, device_id, generation`，明确候选机构和设备。请求正文不携带机构选择，服务器从登录账号派生机构；元数据保留机构用于操作者核对。
- `classes`：`server_id, local_id, name, teacher_id, teacher_name`。
- `students`：`server_id, local_id, external_ref, name, class_id, class_local_id`。
- `lessons`：`lesson_id, class_id, starts_at, charge_units, student_ids`。必须是已核对的服务器真实课次及应到名单，不从班名或星期生成课次。没有历史可用空列表，不能为通过检查造课次。

输出 `body` 可用于候选 `/v1/management/enrollment-reviews`，另有不含姓名的 `metadata`。仍须管理员登录提交并由服务器重新比较规范账本，离线生成成功不等于通过服务器核对，更不等于已经迁移。

## 拒绝条件

- 学号保留前导零，内部ID和学号都唯一；同名不合并，任课不得根据老师拼音猜测。
- 只支持明确当前班级的在读范围；归档学生、无法对应的旧班/转班历史及旧记录缺少班级快照时停止，另行处理，不跳过。
- 同一学生同一天不能对应两个服务器课次，因为当前平板事实无法可靠区分。
- 选定学生的全部本地签到和有效请假必须被映射；签到与请假冲突、漏映射或重复映射时拒绝。
- 签到必须有唯一关联扣课流水，且学生、日期和扣减整数一致。不根据90/120分钟时长推算扣课；当前实际App每次扣100单位，测试中的其他单位只验证显式配置。
- 余额从当前资料读取，不从历史扣课重新计算；充值等非签到流水不推断新生或续费。
- 最终正文超过现有16KB限制时停止，不截断历史或扩大服务器限制。完整学校资料仍需后续分段协议或可信本机导入工具。
