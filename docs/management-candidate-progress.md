# 网页主管理候选版接续（2026-11-01）

## 当前状态

代码位于 `server/management/`，独立于正在使用的 `server/teacher_web/`、冻结的 `business/` 和 `business_next/`。本轮没有部署服务器、升级日常 App、迁移真实学生或更改真实账号。线上仍为平板到网页镜像，不能把本地候选版结果当作真实双向同步已上线。

已完成候选功能：

- 四角色分别校验工作身份；兼任账号不能在教师工作台借用管理员权限。教师限当前任课、专员审批限分配范围，停用/撤权后重试也重新检查。
- 课堂名单、请假/补签申请、管理员/管辖专员批准及驳回；批准与签到/余额变化、不可变事件、审计在一个事务保存。请假保留应到人数且不扣课，补签只扣一次。
- 周/月计划、周/月报告及招生/续费名单周期，规则配置只影响新周期。草稿、提交、版本历史、退回、带原因及期限的管理员解锁、实际提交时间及补交标记。
- 专员手工录分、依据及版本关联。教师重新提交后旧分数保留但不再当作当前版本分数。未提供计算公式，不自动生成分数。
- 本机工作台可实际登录、切换四角色、查看课堂、提交申请、审批和考核材料操作。不是覆盖全部 App 管理功能的完成版。
- 设备交付协议及独立接收模块：服务器按顺序返回最早未确认事件，重复领取返回相同内容与回执令牌；平板完整状态与已应用回执一次保存，成功后才确认。重复交付不再次扣课，冲突不跨过，接收确认本身不修改服务器课时。
- 候选离线签到上行接口：仅当前有效绑定设备可上传，核对课次、日期、应到状态及签到/余额两套版本；扣减取已确认课次规则，不接受任意余额覆盖。固定请求号重复上传只返回原回执，不再扣减。上行接收、账本和不可变回执/审计同事务保存。

## 验证结果与边界

2026-11-01 最终服务端39项测试通过（权限/日期/审批/材料/API/设备交付）；接收端22项测试通过。另一个跨语言完整测试通过：实际 Python 审批事件 → JavaScript 接收并保存虚构状态 → Python 确认回执，重复投递/回执后仍为一次签到、一次扣减。测试只使用临时虚构资料。

同日本机浏览器操作验收：演示账号登录并选择教师 → 当天课堂三名虚构学生 → 提交补签申请 → 切换管理员批准 → 名单显示已签到，余额10变9。完整页面截图在仓库外 `outputs/management-candidate-2026-11-01/approval-result.png`。这是虚构资料操作证据，不是线上或真机验收。

随后新增5项上行测试，并回归设备交付和管理API，18项全部通过：并发精确重试、丢回执、签到与网页批准竞争、网页已请假、错误扣减、时间超前、过期代次、撤权后重试、审计失败回滚、人员账号不能冒用设备接口。竞争结果只有一方成功，余额只扣一次；冲突返回明确错误，保留本地待办等待核对。

现有 App 一次签到扣 **1课时=100整数单位**，课程90/120分钟不等于扣1.5/2课时。迁移应保持当前业务扣减规则。部分核心测试中150单位是验证可配置扣减的虚构数据，不是正式迁移默认值；完整往返测试验证120分钟课仍只扣100单位。

接收模块 `server/management/tablet/approval-receiver.js` **尚未载入日常 App**。它要求经核对的机构/设备/代次、学号/姓名/班级映射、课次名单及两套版本；旧事件写入或旧镜像仍启用、队列未清空、离线签到/请假、余额编辑、任课变化、保存失败都会阻止覆盖。调用方必须提供原子 compare-and-swap 存储，且经现有原生固定服务器身份的加密通道传入；摘要校验不能替代服务器身份认证。

旧快照接口尚未与候选数据库合并，不得直接把现有镜像数据库复制进候选版，也不能用旧快照覆盖新余额。设备授权和逐学生绑定目前仅显式迁移/测试写入，没有自动授权入口。
