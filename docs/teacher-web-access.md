# 教师直接网页登录准备（2026-10-28）

用户要求：老师在各自电脑/手机打开统一网页，使用已经创建的教师拼音账号及现有密码登录，仅查看本人授权班级；负责人保留管理员/教师双身份。教师不需要SSH账号、服务器密码或本机转发脚本。不重新开户，不重置凭证。

当前只有本机SSH转发的只读网页入口；**教师可直接访问的公网HTTPS地址尚未接通**。本轮已准备只读环境检查工具与独立Nginx配置生成器，未读取实际服务器入口状态、申请证书、修改安全组、配置Nginx或完成公网登录验收。

## 数据范围

沿用现有18082只读核对服务、真实用户和任课权限。原服务继续限制业务写入，网页登录/退出仅维护会话；不开放学生修改、课时扣费、设备注册、同步或消息发送。普通教师的数据隔离继续由原业务API强制执行，不能只靠网页隐藏菜单。

网页显示的是已导入服务器的名册/余额快照。平板真实同步尚未开启，新签到、新充值、请假或转班不会自动反映在网页；已有完整历史也未迁移，不能据此展示为实时全校到课率。需要最新资料时先只读核对差异，不自动全量覆盖。

## 无域名的候选方案

可以先使用公共IPv4的HTTPS地址，证书必须覆盖该IP并可自动续期，不能直接用明文HTTP承载教师密码。Let's Encrypt已支持短期IP证书；IP证书有效期短，签发客户端、验证入口及自动续期须先落实。域名后续就绪时再生成对应配置。

参考：[IP证书正式可用说明](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)、[Certbot支持与续期说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)。目前没有申请或安装任何证书，不把草稿中的证书路径当成已经存在。

## 已准备的工具

- `server/ops/inspect-web-entry.py`：只读查询选定端口22/80/443/18080/18081/18082/18183/18443是否监听，以及nginx/caddy/certbot/openssl是否可用、原核对服务状态和限定健康字段。不读数据库、私钥、其他项目配置，不执行sudo、安装、开放端口或重载服务。不把进程列表或其他端口导出。
- `server/ops/check-web-entry.cjs`及ASCII/CRLF入口：负责人一次SSH验证，固定检查程序指纹，通过标准输入执行，只保存最小检查结果到本机私有目录；不保存密码。`--self-check`仅本机校验，不连接服务器。
- `server/ops/viewer-nginx.py`：显式给定HTTPS origin与Linux证书/私钥路径后，仅创建新的配置草稿；无自动安装/替换/重载。支持公共IPv4及规范DNS名称，拒绝明文、路径/凭证注入、私有地址和相同证书/私钥路径。

本机入口在仓库外`outputs/teacher-web-entry-2026-10-28-ready/CHECK-WEB-ENTRY.cmd`；结果保存在`outputs/private-web-entry-2026-10-28/`。迁移电脑时重新生成本机路径与指纹，不依赖原电脑批处理路径。

## 反向代理边界

生成的独立站点草稿仅接TLS；不占用HTTP80、不配置默认虚拟主机、不替换现有nginx.conf。应用仍在回环18082。代理验证指定外部Host和精确Origin（允许不带Origin的正常请求）后，才改为内部回环Host并清除Origin/转发身份头，适配冻结API的LocalGuard；不能跳过外部Origin检查单独清除请求头。

只有两个认证接口允许POST，其余路径仅GET/HEAD，原应用只读守卫继续阻止业务写入；认证请求另有限流，正文上限16KiB，关闭此站点访问日志，不缓存私有响应。教师班级权限、管理员归档权限、登录失败限制仍由原服务核验。

参考：[Nginx代理头与proxy_pass说明](https://nginx.org/en/docs/http/ngx_http_proxy_module.html)。当前只有配置生成/参数边界及检查工具的本机测试，**没有nginx -t实际语法验收或公网端到端验收**。

## 检查后才执行的步骤

1. 读取负责人运行检查后的实际回执，确认18082仍只读/健康，确认现有80/443监听与管理工具；不能因工具存在就推断部署账号有管理权限。
2. 若可使用IP证书，落实证书验证入口与自动续期；否则沿用负责人提供的域名/HTTPS入口。不操作共享项目的私钥或未授权站点。
3. 按实际证书和站点生成单独配置，由具备现有Web服务配置权限的人检查站点冲突、安全组/防火墙及证书SAN，先运行nginx -t，再仅重载对应Web服务。不索要root密码、不扩大部署账号权限。
4. 从外部电脑实际验证TLS、现有8人登录、负责人双身份、普通教师仅本班、跨班/管理入口拒绝、所有业务写入拒绝以及旧网站继续正常，才交付网址。
5. 暂停时只撤除此新增入口配置并按原方式验证/重载，不删除数据库、账号或原核对服务。恢复后资料与凭证沿用。

该网页接入与后续单班真实同步是两件独立工作：先提供只读查看入口，不因此创建真实课次或打开设备同步/微信。
