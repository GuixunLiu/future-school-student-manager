# 正式切换前的暂停与可撤回准备（2026-11-01）

本轮完成候选服务器的迁移准备保护，并接入候选平板队列。**这只是准备/撤回协议，不会激活设备；没有部署到真实服务器，也没有暂停日常系统。**USB仍未识别到平板，后续真机链路尚待验证。

## 工作流

1. 管理员必须先取得尚未过期的新鲜资料核对记录和与其对应的暂存证明。当前角色、设备、代次、期限以及服务器账本摘要均重新检查。
2. 管理员提交原因、固定请求编号，并明确确认“暂停本数据库全部旧镜像写入”。服务器在同一个写事务内保存暂停记录、冻结资料摘要和审计。不更改余额/签到、不创建设备权限、不发送通知。
3. 暂停期间，本机构规范签到上传、审批生效、交付轮询及交付回执暂停；申请可以保存或驳回，考核材料不因此锁定。原始资料管理接口后续加入时必须使用相同事务内守卫，本轮并未补齐全部管理功能。
4. 核对结果需要撤回时，管理员另填原因及固定取消编号。服务器重新计算冻结摘要，完全一致才把暂停状态改为cancelled，不恢复/覆盖任何业务数据。不一致时维持暂停，保留差异人工处理。
5. 重复请求返回原记录，不重新暂停、不延长期限；已取消的准备请求重放也不会再次暂停。权限每次重新检查，审计写失败会回滚整个准备或撤回事务。

## 暂停范围与旧镜像

原镜像的 `web_dataset`、任课显示表和状态表是数据库级单例，因此旧镜像暂停必须覆盖整个数据库，不能只拦试点班。规范业务表按机构隔离，所以签到/审批暂停限对应机构。API回执明确返回两个范围以及当前是否仍有数据库镜像暂停；一个机构撤回不代表其他机构的暂停同时解除。

旧镜像 `receive()` 在同一 `BEGIN IMMEDIATE` 内、认证后且检查历史成功回执前读取暂停表。暂停期间，新的快照和完全相同的旧快照重试都拒绝，不返回成功，不更新数据/任课/版本。如果发现规范余额表却没有迁移守卫表，拒绝旧写入，要求完成显式候选迁移。

**上述守卫只对已更新代码且访问同一数据库的服务有效。**它不能隔空保护另一份旧数据库或仍在运行的旧服务进程。未来部署必须核对所有入口、进程和实际工作库，原线上服务当前没有安装本轮改动。

## 期限和回滚边界

暂停记录保存准备时证明的到期时间，但到期不会自动解除暂停；否则旧镜像可能在无人核对时恢复覆盖。管理员可以在证明过期后撤回，前提是当前身份有效且冻结数据完全未变。

冻结摘要按稳定顺序流式核对本机构完整规范余额、签到、学生、班级、人员身份、任课、角色、审批范围、设备授权、上传/下发记录和绑定，以及本数据库旧镜像数据/状态/回执/待办。非试点班级或教师身份变化也会阻止恢复全库旧写入。审计和规范未生效申请不纳入业务快照，不把正常审计增长当成业务变更。

这不等同于“激活后回滚”。当前状态只有held/cancelled，没有正式激活路由、长期连接期限或客户端切换提交。**后续启用协议必须维持旧镜像拒写，并在双端完成基线确认、备份、模式切换与回执后再开放新业务，不能直接把短期暂存enabled改true。**已有真实新业务后不能靠取消准备恢复旧快照。

## 候选接口

- `POST /v1/management/migration-holds`：`workspace_role=admin, review_id, profile_id, reason, command_ref, accept_database_mirror_pause=true`。
- `GET /v1/management/migration-holds?workspace_role=admin`：本机构最近50项准备状态。
- `POST /v1/management/migration-holds/{hold_id}/cancel`：`workspace_role=admin, reason, command_ref`。

机构从登录账号派生，不接受客户端另行指定；教师、校长、考核专员和设备凭证不能执行这些操作。兼任管理员在教师身份下也不能借用管理员权限。

候选平板将明确的409 `migration_in_progress` 当作临时暂停，保留相同请求和持久队列，不标成永久冲突、不再扣一次课；下发已写本机而回执遇到暂停时，恢复后只重试回执。现有日常App未更新到这段代码。
