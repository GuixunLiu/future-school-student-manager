# 已核对资料修复

版本：4.10.1-local-repair，安卓版本码76。安装与用户操作记录为2026-10-25；最后验收整理于2026-10-27。

## 使用与边界

先在电脑核对最新完整备份，确认真实暂停日期，再生成与该备份全部内容指纹绑定的本地方案。方案不包含人脸、联系方式、密码或设备凭证，不随APK打包或提交源码；实际学生方案仅在本机私有输出目录及用户平板下载目录保管。

后台解锁后进入“设置 → 已核对资料修复 → 打开修复”，选择方案JSON。预览列出姓名/学号及具体修改；用户核对并勾选确认后才能执行。方案过期、已执行、身份/班级/字段不匹配、暂停后存在签到、冲突编号有关联记录、同步已配置或留有同步资料时拒绝执行。

仅允许两类已核实操作：为无关联引用的两人共用编号分配未使用内部编号；按已确认暂停日期，清除与暂停矛盾且包含倒置日期的在读区间。不修改学号、余额、人脸、签到、流水、请假或课表；原区间和编号完整留在本机审计记录中，不补造更早历史。

## 写入与恢复

原生层先保存修复前完整备份，再保存通过整机备份恢复验证的修复结果完整备份。每份文件关闭写入后重新读回，核对UTF-8字节数及SHA-256；任何一步失败均停止。两份文件位于下载目录的`未来学校学生管理系统/资料修复备份`，独立于每日自动备份，不参与14份自动清理。

两份备份成功后，在App私有目录用AtomicFile写入并重读校验修复事务记录，再一次性替换本机资料。保存失败撤销该事务记录，原资料保留；不走普通保存中的人脸缩略图/学习缓存清理回退，不捕获同步事件。

WebView写盘可能延后。若异常退出后仍读到事务记录所对应的原始存储字节，仅恢复先前已由用户确认并验证的修复结果；不是重新自动批准修复。若已持久化或存在后续用户修改，则清理事务记录并保留当前资料。恢复写入失败时保留原资料及事务记录，不自动清空。真实现场人脸识别效果仍需人脸本人验证，不能把描述数据字节未变等同于现场识别验收。
