# 微信家长通知：接入准备与后续边界

更新日期：2026-10-24。当前 App 为 `4.9.4-leave-attendance`（74）。

## 本地请假与后续家长申请边界

v4.9.2 新增老师在解锁后台后代办单次请假。记录使用稳定编号、学生/班级/课日、原因、办理老师、登记时间、`source=teacher_local`、有效/已撤销状态及撤销留痕。v4.9.4 按用户要求调整为请假仍计入应到、不算实到，历史记录自动按新口径重算；请假不扣课时，周报单列，本机催签到仍排除；未来到课须先明确撤假。此功能不依赖服务器、不生成微信发送待办、不建立家长关系，也没有独立教师身份认证。

未来服务号申请需单独开发：微信本人身份和学生关系核验、家长提交、是否需老师审批的业务规则、服务器授权及审计、平板同步和离线冲突处理。家长申请不可以直接伪装为本地已批准请假；在线端身份/权限由服务器校验，不能信任客户端填写的老师姓名。上线前需明确审批生效时点、已签到/已撤销/调课冲突、同步去重及重试、解绑和通知策略，并经测试家长验证后才启用。本次没有自动上传本地历史请假或学生资料。

## 本版已完成

App 继续以平板本地数据为主，没有迁移学生数据库，也没有接入外部服务。

- 入口：后台设置 → 微信家长通知；学生表格 → 家长通知。
- 接入设置、家长接收意向、本地通知待办；所有入口需先解锁后台。
- 意向只能由管理员在真实取得家长同意后登记，标记明确为“未绑定微信”。没有手机号查微信、手动伪造绑定、输入 OpenID 或 AppSecret 的入口。
- 本地准备默认关闭，补签准备另有默认关闭的开关。开启不补录以前签到，取消后重新启用不恢复已取消待办。
- 生成待办与签到及课时扣减在同一份本地状态中提交；保存失败整体回滚。签到撤销会取消对应待办。取消通知意向、关闭准备或排除补签，同步取消相关未发送待办。
- 只保存对应学生编号、学号、姓名、该次班级/教室、签到日期/时间、补签标记、意向登记时间及本地状态，不复制人脸、照片、联系方式或课时流水。
- 每页 40 条、支持搜索；总量上限 2,000 条。满额时签到照常进行，界面提示并累计未生成次数；由管理员确认清理已取消记录，不静默删除未取消记录。
- 删除学生会清理本机对应通知资料；恢复备份只恢复本地记录，不建立任何远程发送任务。

本地待办不是“发送队列”，`prepared` 不代表服务器接收或家长收到；`cancelled` 仅为本地取消。当前没有 `sent`、`delivered` 或微信绑定成功状态。

## 后续待实现，不属于本版完成内容

1. 审核通过后选择实际适用的微信模板，核对真实字段、通知场景及平台要求。
2. 确定通知服务部署位置、域名、必要的网络配置及费用，由用户确认后部署，不自动购买。
3. 在服务端保管微信凭据和令牌；App 仅持有可撤销的设备身份，不将微信 AppSecret 打包进 APK、日志、Git 或客户端备份。
4. 实现家长本人微信授权、关注状态与学生关系核验。学生编号不可充当绑定密码；不能凭姓名或手机号相同就绑定。支持撤销授权、解绑，以及多个家长/多个孩子的独立关系。
5. 上线前由用户核对并确认数据范围、家长说明及接收选择；先以测试家长验证一条消息，不能直接对真实全校学生群发。
6. 签到本地提交成功后，再异步提交最小通知事件。通知失败、断网或解绑不能撤回签到、重复扣课或阻塞界面。
7. 服务端按机构、设备和事件编号联合去重；超时重试不得重复发送。App 同时显示提交结果和微信回调结果，不能把 HTTP 成功当成送达或已读。
8. 正式发送的撤销需要分情况：尚未发送则取消；已经发送不能谎称撤回，可根据可用模板及用户确认发送更正。所有状态变化保留可核验记录。
9. 离线事件设置明确有效期及重试退避；过期、补签、解绑后或历史导入数据不得自动补发。恢复到另一台设备需重新注册和确认，不复用旧设备身份造成重复通知。

当前 `prep:<attendanceId>` 仅在本机用于去重。后续发送接口不得原样将它用作跨机构全局键；须加入机构和设备身份，并单独定义版本化事件协议。

## 升级与验收

升级默认不启用准备、不登记意向、不回填历史记录，不改原学生、课时、排课或签到。旧备份没有 `wechatNotices` 时继续兼容。

专项脚本 `wechat-preparation-regression.cjs` 使用独立示例数据与本机页面，并阻断所有外部请求。可通过环境变量 `PLAYWRIGHT_MODULE` 与 `CHROME_PATH` 指定本机浏览器测试依赖。仓库截图来自同一示例环境，不使用平板中的真实学生资料。
