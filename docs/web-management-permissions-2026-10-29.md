# 网页管理权限与考核规则接续

记录日期：2026-10-29。依据用户上传《系统角色权限与考核时间规则.docx》全文（含全部权限表），以及最新“网页承担管理、平板主要签到”的要求。本文件是需求核对记录，不代表功能已实现或已部署。原始文件保留在用户提供的位置，不复制到仓库。

## 最新目标与当前差距

网页成为主要业务管理入口，教师能办理本人任课学生的请假与补签，管理员可在网页完成原平板管理功能。保留已有账号、多身份选择和 App 风格。平板主要承担签到，具体移除旧管理入口应在功能迁移、数据一致性和用户验收完成后进行，不能提前停用。

当前 `server/teacher_web/api.py` 只支持 teacher/admin 工作身份、课程/周报查看和待确认补签申请；`mirror_store.py` 接受平板完整只读快照。首次真实上传已由用户确认“网页已更新”。现有协议不是双向编辑，不能直接增加网页写按钮后仍用旧快照覆盖服务器。

实现需明确服务器统一业务记录与平板离线签到的衔接：稳定记录编号、操作来源、版本冲突、幂等回执、一次扣课/撤销返课及断网恢复。先在虚构数据验证，再对当前工作库做有备份的迁移。不得重导旧账号库覆盖当前账号/角色，也不得重放历史签到。

## 文档明确的四类身份

| 身份 | 权限 |
| --- | --- |
| 校长 | 全局只读看板、统计和教师提交材料；不能操作账号、签到、申请、审批、原始数据或系统配置；允许受限导出 |
| 管理员 | 账号/角色、系统配置、数据管理与修正、签到代操作、申请与审批、全局看板、导出、日志；可退回考核材料、解锁逾期提交 |
| 教师 | 仅本人任课班级数据；发起签到、提交请假/补签申请；填写本人计划、报告、招生/续费名单；不能审批、导出、修改系统权限 |
| 绩效考核专员 | 全校统计及全员考核材料查看/导出、退回重交、计算及录入考核分数；仅审批被分配范围内的请假/补签，不修改学生、班级或课时原始数据 |

多身份账号继续先选工作身份，页面和接口均以当前身份限制权限。管理员兼教师填写本人考核材料时应切换教师身份，不因兼任而绕过教师审批限制。

## 考核模块与时间

教师填写的周计划、周报、月计划、月报与现有自动统计的到课率周报是不同数据，需独立保存和命名，不覆盖历史统计。

| 项目 | 文档规定的默认截止 |
| --- | --- |
| 周计划 | 每周二 09:00 |
| 周报 | 每周日 18:00 |
| 月计划 | 每月 1 日 09:00 |
| 月报 | 每月最后一天 18:00 |
| 招生名单、续费名单 | 按实际周期配置，记录实际录入时间 |

截止时间由管理员配置，不硬编码。时间按现有机构北京时间处理；周期起止、截止边界和配置变更对已创建周期的影响需有明确实现与测试。

- 截止后禁止继续编辑；教师联系管理员解锁。
- 解锁记录操作者、时间、教师、原因，解锁日志不可删除。
- 截止后提交（含解锁后）标为补交，记录实际提交时间并在导出显示。
- 已提交绿色、补交黄色、逾期未提交红色、未到截止灰色并显示剩余时间。
- 每天凌晨扫描逾期；请求处理也必须实时验证截止，不能依赖凌晨任务才锁定。
- Excel 导出包含导出人和导出时间，保留补交标记。
- 权限必须同时在页面和接口验证。

## 用户已确认的冲突处理

1. 用户明确选择“可以计算和录入考核分数”。专员拥有计分/录入权限；计算公式未提供，不能自行编造考核标准。
2. 用户明确选择“网页审批后生效并同步平板”，替代旧的平板确认模式。审批与业务生效应在服务器同一事务内完成，设备接收状态独立记录；不把等待设备回执显示成待审批，也不在设备再次扣课。
3. 用户确认专员可看全校统计和全员考核材料，只审批被分配范围内的申请，不修改学生、班级、课时原始数据。审批引发的受控业务变化与直接编辑原始数据权限分开。

其他需在对应模块细化：校长受限导出的具体列/范围；专员管辖范围分配；招生/续费统计周期；退回后遇到截止是否还需管理员解锁。不能自行把未明确范围扩大为全量写入。新角色人员尚未指定，不自动给现有账号追加身份。

## 后续实施与验收顺序

1. 固化确认后的权限矩阵、审批状态流与审计，覆盖身份切换、越权、停用账号和任课变更。
2. 建立可迁移的服务器业务模型和双向同步，验证网页修改不会被旧平板快照覆盖、离线签到不会重复扣课、请假与签到冲突能明确处理。
3. 教师网页请假/补签申请及审批闭环，管理员学生、课程/班级、任课、排课/隔周、课时/续费、归档、历史统计、导入导出、设置等逐项与 App 对照验收。当前提高班 120 分钟、其他课 90 分钟仅为默认值，允许后续调整。
4. 四角色工作台与考核材料提交、退回、截止锁定、解锁补交、审计和导出。
5. 保留当前账号和历史数据，准备更新/回滚工具，验证后逐步上线；平板收敛到签到用途。微信和家长自助仍为后续范围，不随此需求自动开启。
