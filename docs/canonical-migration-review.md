# 迁移资料核对到连接授权（2026-11-01）

## 当前候选工作流

1. 已明确授权的管理员，以管理员工作身份提交候选设备的最小资料清单、完整平板资料摘要及实际采集时间。
2. `review_enrollment` 核对全部已绑定学生（不能遗漏或增加）、稳定服务器ID与本机ID、唯一学号、姓名、当前班级、本机班级映射、规范余额，以及全部相关课次事实。教师必须是服务器已启用且仍有教师身份的唯一任课账号，不能仅凭姓名标签自动创建或授权。
3. 全部一致才保存不可变核对记录与审计，返回 `review_id`。只写核对元数据，学生、班级、账号/角色、设备授权、签到、余额均不改变。任何差异不会发放证明。当前实现对差异返回409，不自动修复或替用户选择合并方案。
4. 管理员引用该核对记录授权暂存连接，服务器重新检查管理员身份、设备/代次、核对期限和当前账本摘要，再写入证明。证明与设备nonce、连接ID、平板摘要和服务器摘要绑定，不自动产生设备token、班级绑定或启用新同步。
5. 相同授权重试返回已有证明；不同配置不能覆盖原代次证明。过期证明只有在**新鲜且相同基线重新核对**后才能续期，记录审计，重复请求不延长有效期。基线变化则需显式新的代次迁移处理，不能覆盖旧代次。

## 时间与范围限制

- 资料采集必须在最近15分钟内，允许最多120秒设备时钟超前；实际采集时间不能用现在时间替代旧文件时间。核对期限取采集后15分钟与核对后15分钟中较早时间。
- 暂存证明有效期还受设备和同步授权最早到期时间约束。**这是暂存/迁移窗口，不是激活后长期连接有效期。**正式激活协议尚未实现，后续必须重新确认基线并取得正式有效期，不能直接把暂存profile的enabled改true。
- 对学生、余额、任课、签到或设备范围的变化都会使旧核对失效；撤销教师身份也会改变账本摘要。撤销管理员身份后，旧请求不能借已通过核对继续授权。
- 仅处理已存在且显式授权的候选设备、绑定和规范账本，不导入原始备份、不迁移历史、不从课长推算扣课、不创建新教师、不更改真实服务器。当前候选清单要求每班唯一教师；多教师、归档或无法对应的历史必须另外处理，不能跳过。

## 接口与字段

`POST /v1/management/enrollment-reviews`：`workspace_role=admin, device_id, generation, baseline_sha256, source_captured_at, source`。

`source` 只允许三项，禁止联系方式、人脸等额外字段：

- `classes`：`server_id, local_id, name, teacher_id, teacher_name`。
- `students`：`server_id, local_id, external_ref, name, class_id, class_local_id, balance_units`。
- `facts`：`lesson_id, student_id, status, expected, charge_units, starts_at`。`expected`必须布尔，课时为百分之一课时整数。

`POST /v1/management/enrollment-authorizations`：`workspace_role=admin, review_id, profile_id, nonce`。机构从账号派生，客户端不能指定其他机构。返回暂存证明元数据，不返回设备密码。

接口仍受16KB请求体上限约束，适用于先前的单班试运行清单。全校清单需要后续可信服务器本机工具或分段核对协议；**不要放宽请求限制或直接把整个含人脸备份上传**。源资料的稳定ID映射和采集工具尚待完成，不要把手工拼接的源清单视为真实备份已经迁移。
