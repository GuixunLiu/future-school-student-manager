## 分段协议

候选新增 `management_enrollment_batches` 和不可改删的 `management_enrollment_pages`，通过现有显式候选初始化创建。启动检查要求表存在，不自动升级生产库。既有单次核对复用同一事务内的 `_record_enrollment_review`，原严格身份、当前唯一任课、完整绑定集合、逐条事实、余额及新鲜时间验证不变。

| 接口 | 行为 |
| --- | --- |
| `POST /v1/management/enrollment-batches` | 管理员当前工作身份创建短期核对批次，声明三个分区的行数、页数、完整摘要，绑定设备/代次/原始采集摘要和当前服务器账本摘要 |
| `POST /v1/management/enrollment-batches/{id}/pages` | 同机构、同创建人上传固定分区/页号/摘要/最小字段；可乱序，原样重复幂等，改内容不能覆盖 |
| `POST /v1/management/enrollment-batches/{id}/finalize` | 完整页号、总行数、每页和全分区摘要核对后，执行原始全量核对；写核对记录、完成批次和审计同一事务提交 |

每段最多100行、ASCII规范JSON最多12KB；每请求仍不超过16KB。全批最多500段；班级1000、学生2000、事实10000，不截断。每设备最多3个未过期开放批次。没有事实时声明0行/0页和空数组摘要，不插入虚构事实。

批次最长15分钟，并受实际采集时间、设备和代次授权到期限制。重复开始不会延长原期限；每页、完成及重复完成重新验证当前管理员身份、设备/代次和账本摘要。另一管理员、另一机构和设备令牌不能借用已有批次；改了余额、绑定、任课或老师角色后不能沿用旧批次。

完成记录落库后再发生最终审计失败时，整笔回滚，保留原段待查；不会留下“批次完成但无核对”或孤立核对记录。并发完成只有一份核对记录；丢回执/新进程读取原完成结果，不生成第二份。后续仍要显式 `enrollment-authorizations` 及原生暂存，结果仍 `enabled=false / activation_required=true`。

## 清单工具

`server/ops/pack-enrollment-review.cjs` 只打包，不联网、不拿账号密码。按与Python `encoded()` 相同的ASCII、排序键、紧凑JSON生成分区/段摘要；Unicode、非BMP名字及整数百分之一课时可跨语言核对。

`build-canonical-manifest.cjs` 保留原 `build/buildNative` 单次接口，新增 `buildSegmented/buildNativeSegmented`，CLI可加 `--segmented-ref <明确请求号>`。输出仍须在Git外、原文件不可覆盖。全校分段模式须覆盖原平板全部在读学生，漏掉任何一人停止，防止全局新写入门禁只接通试点16人。新模式仍要求原始字节/摘要/真实采集时间及每条已选历史唯一映射；不放松同名/转班/旧班不明、关联扣课、过期或未映射历史检查。

因此，不能给17:31旧备份重新标记当前采集时间，不能仅使用当前镜像的483节明细掩盖另外72条原始记录，也不能直接把全校旧备份强塞进本轮分段接口。历史边界及初始化要先完成。
